# Donkey Kong clone — working notes for Claude

Arcade-faithful 25m + 100m with kid additions (invulnerable mode, presets and
knobs). Follows `../GAME-SPEC.md` and the conventions of `../pac-man/`.

## Run / verify

```
node tools/launch.js          # or double-click index.html (file:// works, no network)
node tools/test.js            # headless suite under node; must end "all tests passed"
node tools/render-frame.js    # real frames -> reference/out/*.png (view with the Read tool)
node tools/build-sprites.js   # regenerate the SPRITES block in index.html from reference/
```

`test.js` extracts the IIFE from `index.html` (everything between `<script>` and
`</script>`), appends an export of internals (`globalThis.__DK`) and runs the real
`update()`/`render()` under `harness.js`. `render-frame.js` does the same with a
software canvas so PNGs can be produced. If you change the tail of the IIFE
(`})();`) both tools break.

`index.html` also exposes `window.DK_DEBUG = { game, settings, high, step(n) }`
so browser automation can step frames even when the tab is in the background
(Chrome stops `requestAnimationFrame` in hidden tabs). The Chrome extension
refuses `file://`, so for in-browser checks serve the folder with any static
server; the game itself needs nothing.

## Conventions worth knowing

- Positions: Jumpman's `(x, y)` is the left of his 16 px box and his **feet**;
  barrels likewise (bottom at the floor). Native Jumpman frames face **left**;
  `draw(name, x, y, flip)` mirrors for right. The hammer frames are 30x26 with
  Jumpman's box at (14,10) inside them, so a left-facing hammer frame is drawn
  at `x-14`.
- Girder floors are step functions (1 px every 16 px); Jumpman bobs along them
  like the arcade. Ladders snap him to `l.x - 4`.
- Broken ladders: `up` = stub below the upper girder, `down` = stub above the
  lower girder, both measured from the real frame. Jumpman can climb the stubs
  and stops; barrels take them and fall through the gap.
- The two long ladders at x=64/80 on 25m are `exit: true`: reaching their top
  (y=56, Pauline's level) wins, and they are drawn up to y=32 like the arcade.
- Rivets leave an 8 px hole in the girder (`game.holes`); walking into one
  makes Jumpman fall (40 px -> death unless fall damage is off).
- The arcade's "800 shown, 500 paid" for jumping 3+ objects is intentional.
- Text colours: `text(str, x, y, PAL.X)`; the font glyphs are stored as `W`
  and tinted via a recolour map whose value is a hex string.

## Palette (`PAL`, sampled from the real frames)

W white, R `#ff0000` Mario red, B `#0000d8` Mario blue / L=01, S `#ffb855`
skin, O `#ff6800` barrels/Kong face, D `#b80000` Kong fur/hammer head,
P `#ff44aa` items, M `#f057e8` Pauline, C cyan ladders, L `#0000ff` 100m
girders/oil drum, Y `#ffb600` 100m ladders/rivets, G/g the 25m girder pink/red.

## Gotchas already paid for

- `rasterise()` maps letters through `PAL`; a recolour value starting with `#`
  is used directly (that is how tinted text works). Before that fix all text
  came out magenta.
- Wild barrels must ignore the girder they just bounced from (`passG`) or they
  bounce forever in place.
- Chrome's extension can't open `file://` and pauses rAF in background tabs;
  use `DK_DEBUG.step()` for automation.
- The j-saro Mario sheet's box background is the same dark blue as Mario's
  shirt, so Jumpman frames come from the Mario Wiki PNG/GIFs instead
  (`tools/gif.js` decodes the run/hammer GIFs).
- Large bash heredocs fail in this environment; use the Write tool and small
  node patch scripts.
